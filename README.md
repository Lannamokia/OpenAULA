# OpenAULA

AULA 键盘的**非官方开源驱动**：Tauri v2 + Rust + Vite/TypeScript，脱离官方网页驱动独立运行。

> ## ⚠️ 只在一把键盘上验证过
>
> 目前**只在 AULA HERO 68 XS**（固件 23.0.1，有线 PID `0x103E` + 8K 无线接收器 PID `0x106C`）
> 上做过真机验证。厂商用同一套协议驱动多款机型，所以其它型号很可能也能用，但**没有验证过**。
>
> 换型号请自担风险，建议按这个顺序试：
> 1. 先跑只读探测（`cargo run --example probe`）——它**不发任何写命令**，只读 UUID/固件/电量/键位/宏/灯区状态；
> 2. 能读之后，再逐个页面试写操作；
> 3. 写操作一律按「读原值 → 写 → 读回 → 还原」来做。
>
> 与 AULA 官方无关系，商标归其所有者。写命令会修改键盘的板载存储。

## 它能做什么

| 页 | 功能 |
|---|---|
| 设备 | 枚举并打开配置接口（按 `usage_page 0xFF60 / usage 0x61` 过滤），连接时探测设备是否在响应 |
| 设备信息 | 电量、固件、UUID、当前板载配置 |
| 改键 | 三层键位（基础 / Fn / Fn1）读写；7 类键码选择器 + 搜索 + hex 手输；宏绑定；已配高级键的键位标记 |
| 高级键 | TGL / MT / DKS / SOCD / MPT / END / RS 七种高级触发功能的增删改查 |
| 触发设置 | 触发点（按键多深才触发）、快速触发 RT、顶部/底部死区、轴体（选择/应用/校准）、实时行程测试 |
| 宏 | 宏列表 + 动作编辑器 + 按键录制 + 容量估算 + **绑定到任意层的任意键** |
| 灯光 | 四个灯区的效果/颜色/亮度/速度、独立 OFF/ON 开关（记住原效果）、全键单色、逐键改色、自定义区持久化 |
| 神光同步 | 系统音频频谱驱动键盘灯（纵向频谱柱）+ Windows 主题色写入主灯/侧灯。**无线下会闪烁，实际只有有线可用**（见下文） |
| 板载配置 | 三套配置的切换与改名，标记当前配置 |
| 系统设置 | Mac 模式、Win 键锁定、回报率、自适应校准、连击优化、消抖、低功耗、休眠、WASD 互换、侧灯同步 |
| 原始命令 | 直接收发任意 `cmd / param / data`，排错用 |

## 怎么跑

需要 **Node 20+**、**Rust 1.80+**、Windows（本项目只针对 Windows；协议层没有平台依赖，但窗口/音频采集部分是按 Windows 写的）。

```bash
npm install          # 前端依赖 + @tauri-apps/cli
npm run tauri dev    # 开发模式（Vite + cargo tauri dev）
npm run tauri build  # 打包桌面应用
```

只检查 / 不打包：

```bash
npm run build                    # 前端：tsc 类型检查 + vite build
cd src-tauri
cargo check --all-targets        # Rust 检查
cargo test --lib                 # 单元测试（协议编解码）
cargo run --example probe        # ★ 只读真机探测，不写任何东西
```

`probe` 会打印：接口列表、UUID、固件、电量、三套配置名、一条键位、宏区、高级键、四个灯区、
触发能力与各项当前值、整机开关。**怀疑设备状态时先跑它。**

### 两条链路，行为不同

两个配置接口都是 `usage_page 0xFF60 / usage 0x61`、**report ID 都是 9**，但**报告长度不同**
（读 HID 报告描述符实测）：

| | 有线（如 `0x103E`） | 8K 无线接收器（`0x106C`） |
|---|---|---|
| 接口报告 | Input / Output **各 63 字节**（上线 64） | Input / Output **各 19 字节**（上线 20） |
| 传输 | 63 字节应用包**整包直发** | `0x66` 分帧（5 片）+ **逐帧 ACK** 握手 |
| 一次命令耗时 | 亚毫秒 | 约 35ms（分片间隔 1ms；0ms 在持续负载下只有 16% 成功率） |
| 写命令 | 发完事，**不等应用层应答**（但设备会回送，见下） | 发 5 片 + 短暂收 ACK 收尾 |
| 行程监测 | 每拍一次快照，可到 ~250Hz | 受往返限制，约 30Hz |
| 校准进度上报 | 有 | **没有**（只能触发校准，看键盘上变绿） |
| 回报率档位 | 影响不大 | 影响无线上行带宽；**与音乐律动的闪烁无关** |
| 音乐律动（神光同步） | ✅ 正常 | ❌ **会闪，见下** |

> 无线接口**只收 19 字节**这件事本身有含义：主机交给接收器的永远是 `0x66` 的**分片**，
> 63 字节应用包是**接收器自己重组**的。它有自己的状态机，主机看不见也管不着。

读取路径是**事件驱动**的：一个常驻读线程用第二个 HID 句柄阻塞读，报文进队列，上层从队列取。
别改成"固定窗口轮询 `read_timeout`"——Windows 上带超时的等待会被量化到约 15.6ms 的系统
计时器粒度，实测刷新率封顶 64 次/秒、行程流只能收到约 2% 的包。

### ⚠️ 音乐律动在无线下不可用

无线链路上逐帧下推"逐键颜色"，键盘会**周期性整块变成另一个颜色**（白或杂色）。范围如下：

- **与帧率无关**：50 / 100 / 150 / 220 / 300 / 496 报文每秒，每一档都会发生
  （速率只影响每次异常被下一帧刷掉的速度，所以看起来"高速更干净"）；
- **与下发通道无关**：无线快通道（`*ByWireless` 裸报文）与标准通道（`0x08/1` 逐片 ACK + 重传）
  在同一帧率下表现相同——两条通道的传输实现没有共同点，故障出在共用的环节；
- **有线正常**。

因此无线下不应做逐键颜色推流：检测到无线链路时页面会提示，并在点「启动」时弹确认框。
官方驱动同样只在有线下提供音乐律动（且只是个响度计，不是频谱）。

## 协议

完整协议文档（逐命令的 cmd / param / 参数 / 应答）在本仓库 `docs/` 里：

- `docs/protocol.md` —— 链路层与应用包信封
- `docs/commands.md` —— 每条命令；灯光、宏、高级键、磁轴触发、事件、无线裸报文、legacy `AA` 族
- `docs/keycodes.md` —— 键码表、组合键编码、Fn 层功能键

协议由反混淆官方网页驱动 + 真机报文对照还原而来。**读代码前建议先读 `DEVNOTES.md`**，
里面记着踩过的坑与实测结论（不少结论与直觉相反，例如：

- `0x98/0x01` 不是"流"而是**一次快照**，重发频率就是采样率；
- `0x85/0` 是"按请求长度读宏区"，不是查表长；宏表长要从第一条表项的 offset 推；
- 宏动作 byte0 的 bit4-6 是**按键类别**（普通/修饰键/鼠标），不是"设备类型"；
- 写命令不要等**应用层**应答，设备不回；
- **设备会回送**：每一条**输出报文**都会在输入端点上原样回送，**末字节被替换成
  `255 - Σ(该报文前 19 字节)`**。若读取时只认 63 字节的 `0x66` 事件包，这些回送会被全部丢弃；
- 无线裸报文通道**有 8 位校验和**（`255 - Σ`，含 report ID），而且**接收器会验**：
  坏校验的报文被丢弃、从不显示。但它**不防丢包**——没有 ACK、没有重传、没有帧序号，
  一帧少一条就是残帧（**残帧会被整体丢弃，不会画一半**）；
- 无线设备"突然不应答"**第一嫌疑永远是休眠**，不要用单次观测下因果结论）。

## 已知限制

- **只在 HERO 68 XS 上验证过**（见文首）。
- **无线下音乐律动会闪**（见上），页面有常驻提示与启动前确认框；**要用就接有线**。
- 无线下**校准进度没有回报**，界面只提供起停 + 提示看键盘灯。
- `0x86/0`（读自定义灯光区）**批量读**在本机固件会返回错位数据，驱动改成逐个读并校验回显 id。
- Logo / 灯箱灯区在 HERO 68 XS 上**不存在**（写入被 ACK 但读回不变）。
- 官方 SDK 里那套 legacy `AA` 命令族（灯箱 / 侧灯 / **音乐数据** / GIF / TFT / 磁轴 DKS）在本机
  **不通**：它写死用 **report ID 0** + 32/64 字节报告，而本机两个接口只声明 report ID 9，
  按它的分包逻辑实发也没有任何 `0x55` 应答。
- 安装包：用 Inno Setup 打包，脚本在 `installer/`（`tauri build` 只产 release 二进制）。

## 开发约定

- 任何写操作按「**读原值 → 写 → 读回校验 → 还原**」做；写宏区**必须先整段读**（设备会把写入长度之外置 `0xff`）。
- 新增 `#[tauri::command]` **必须同时在 `src-tauri/src/main.rs` 的 `generate_handler!` 里注册**，
  否则前端只会得到一句 `Command xxx not found`。自查脚本见 `DEVNOTES.md`。
- 面向用户的文案不写协议细节与实现内幕（有「原始命令」页专门给排错用）。
